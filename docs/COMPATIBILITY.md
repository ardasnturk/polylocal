# Compatibility Matrix

Tested with `tools/compat/run.sh` (and `tools/compat/testpage.html` for browsers). Each row shows how text is read and written in an app. The path information comes from the app's diagnostic log, which never records the text itself:

```bash
log stream --predicate 'subsystem == "dev.polylocal.app"'
```

| App | Field | Read (⌘C C) | Replace | Selection position | Notes |
|---|---|---|---|---|---|
| TextEdit | text | ✅ AX | ✅ AX | ✅ | |
| Safari | textarea / input / contenteditable | ✅ AX | 🟡 paste | ✅ | The web view ignores AX writes; the paste fallback works |
| Chrome | textarea / input / contenteditable | ✅ AX | 🟡 paste | ✅ | Same as Safari |
| VS Code | editor | ✅ AX (clipboard on first try) | 🟡 paste | ❌ | Electron builds its AX tree after the first request; the app now retries after a short delay |
| Pages | — | — | — | — | Not tested |
| WhatsApp, Discord, Messages, Mail | — | — | — | — | Not tested automatically: a stray ↩ could send a real message. Test by hand |

### Inline suggestions (Mode C)

| App | Suggestion | Replace with Tab | Notes |
|---|---|---|---|
| TextEdit | ✅ | ✅ AX | Esc and ⌥Tab verified; no suggestion appears for text already in the target language. Sentence completion also works |
| Safari, Chrome, VS Code | — | — | Not tested. In web fields, replacement will use the paste fallback; check whether `AXValueChanged` notifications arrive |

**Legend:** ✅ works via AX · 🟡 only via the clipboard/paste fallback · ❌ does not work · — not tested

Tested: 2026-11-01, macOS 27.0.1, Gemma 4 E4B (llama.cpp).

## Known conflicts

- **⇧⌘C C and clipboard managers:** if Raycast's "Clipboard History" is bound to ⇧⌘C, both windows open and ↩ goes to Raycast. Fix: choose a different shortcut in Settings → General → Shortcuts (e.g. ⌃⌥C, single press). ⌘↩ in the ⌘C C popup performs the same replace action.
- **Clipboard history:** the app's temporary clipboard writes (paste fallback, restoring the clipboard) are marked with the nspasteboard.org types (`TransientType`, `AutoGeneratedType`), so clipboard managers do not record them. Your own ⌘C is recorded as usual.
